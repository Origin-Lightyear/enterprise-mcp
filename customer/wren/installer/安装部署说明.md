# Wren 一键安装部署说明

本目录提供每客户实例独立部署 Wren Adapter 的安装器：

- `install-wren-linux.sh`：安装 Python 环境、复制锁定的 Wren 源码、注册 systemd、启动并检查健康状态。
- `install-wren-windows.ps1`：安装 Python 环境、复制锁定的 Wren 源码、注册 SYSTEM 开机计划任务、启动并检查健康状态。
- `profiles.yml.example`：MySQL profile 示例，密码使用环境变量占位符。
- `wren.env.example`：密钥环境文件示例。

两个安装器均具有以下行为：

1. 校验 Python 3.11+ 和交付目录。
2. 为实例创建独立 runtime、虚拟环境、project、profile 和配置目录。
3. 安装本地 `customer/wren/upstream` 锁定版本、选择的数据源 extras，以及固定版本的 LanceDB 向量索引依赖。
4. 保留已有 `runtime.previous` 和 `venv.previous`，新进程健康检查失败时同时恢复旧源码和旧依赖环境。
5. 只监听 `127.0.0.1`，不开放 Wren MCP Server。
6. 不覆盖已经存在的客户 MDL project；重复执行可用于更新 Adapter/Wren runtime。

安装器固定使用当前副本验证过的 `wren-core-py==0.8.0`。其他 Python 依赖遵循上游 `pyproject.toml` 的约束；正式离线交付应建立经过漏洞扫描的内部 wheel 仓库或完整 lock 文件。

安装后的健康检查验证 Adapter 进程和 MDL 能正常加载，不代表真实数据库连接已经成功。数据库连接仍需通过 customerapp 管理接口的连接测试或 Wren `dry-run` 在真实环境单独验证。

## 准备数据库配置

复制示例并修改非敏感连接信息：

```bash
cp customer/wren/installer/profiles.yml.example /tmp/profiles.yml
cp customer/wren/installer/wren.env.example /tmp/wren.env
```

`profiles.yml` 中保存 `${CUSTOMER_DB_PASSWORD}`，实际密码只写入 `wren.env`。不要把修改后的密钥文件提交到仓库。

常用 extras：

| 数据源 | `--extras` / `-Extras` 值 | 额外系统依赖 |
|---|---|---|
| DuckDB、本地文件 | 留空 | 无 |
| MySQL | `mysql` | Linux 通常需要编译器、Python headers 和 MySQL/MariaDB client headers |
| PostgreSQL | `postgres` | 使用 psycopg binary，无额外编译通常可用 |
| SQL Server | `mssql` | 需要 Microsoft ODBC Driver 和 unixODBC（Linux） |
| 多种数据库 | `mysql,postgres,mssql` | 同时满足各驱动系统依赖 |

其他可用 extras 以 `customer/wren/upstream/pyproject.toml` 为准。安装器不会自动修改操作系统软件源或安装数据库厂商驱动。

LanceDB `0.38.0` 由安装器固定安装，不需要在 extras 中手工选择 `memory`。本项目使用员工 NewAPI 提供的 Embeddings endpoint，不下载官方 `sentence-transformers` 本地模型。首次查询新的 `sourceKey + mdlDigest + embeddingModel` 组合时会构建索引，几百张表的首次请求可能持续数分钟；后续请求复用派生索引。员工 API Key 不写入索引。

安装器会把 `NOTICE.md` 放入 runtime。正式向客户分发前还必须按 NOTICE 要求随包提供 Apache License 2.0 正文，并完成 Python/Rust 传递依赖许可证和漏洞扫描。

## Linux 一键安装

前置条件：systemd、`curl`、Python 3.11+，并把整个 `customer/wren` 目录放到服务器。

```bash
sudo bash customer/wren/installer/install-wren-linux.sh
```

不带参数时会进入交互安装向导。实例 ID、端口、目录和可选配置文件会逐项询问；数据源驱动和最终确认使用键盘菜单：

```text
↑/↓    移动选项
Space  多选或取消数据源驱动
Enter  确认当前选择
```

安装前会显示完整配置摘要，可选择“开始安装”、“返回修改”或“取消”。

默认目录：

```text
/opt/enterprise-mcp/<instance-id>/wren/       runtime 和 Python venv
/var/lib/enterprise-mcp/<instance-id>/wren/   MDL project、profiles 和运行状态
/etc/enterprise-mcp/<instance-id>/wren/       密钥环境文件
/etc/systemd/system/enterprise-wren-<instance-id>.service
```

常用运维命令：

```bash
systemctl status enterprise-wren-tenant-10000-mcp-20001
journalctl -u enterprise-wren-tenant-10000-mcp-20001 -n 200 --no-pager
systemctl restart enterprise-wren-tenant-10000-mcp-20001
curl http://127.0.0.1:8091/internal/health
```

安装器默认根据实例 ID 生成稳定的短 Linux 用户名。需要与现有运行账户统一时可以显式指定：

```bash
sudo bash customer/wren/installer/install-wren-linux.sh \
  --instance-id tenant-10000-mcp-20001 \
  --service-user enterprise-wren-20001
```

## Windows 一键安装

前置条件：管理员 PowerShell、Python 3.11+、Windows 任务计划程序。生产应使用所有本机用户可读取的 machine-wide Python，避免 SYSTEM 任务无法访问仅安装在个人目录中的 Python。

```powershell
Set-ExecutionPolicy -Scope Process Bypass
& .\customer\wren\installer\install-wren-windows.ps1
```

Windows 向导的操作方式与 Linux 一致：使用 `↑/↓` 移动，使用空格键多选数据源驱动，使用回车键确认。安装前同样会显示配置摘要并允许返回修改。

默认目录和任务：

```text
C:\ProgramData\EnterpriseMcp\<instance-id>\runtime
C:\ProgramData\EnterpriseMcp\<instance-id>\venv
C:\ProgramData\EnterpriseMcp\<instance-id>\data
C:\ProgramData\EnterpriseMcp\<instance-id>\config\wren.env
计划任务: EnterpriseMcp-Wren-<instance-id>
```

常用运维命令：

```powershell
Get-ScheduledTask -TaskName "EnterpriseMcp-Wren-tenant-10000-mcp-20001"
Stop-ScheduledTask -TaskName "EnterpriseMcp-Wren-tenant-10000-mcp-20001"
Start-ScheduledTask -TaskName "EnterpriseMcp-Wren-tenant-10000-mcp-20001"
Invoke-RestMethod http://127.0.0.1:8091/internal/health
```

Windows 安装器将环境文件和 profile ACL 收紧为 SYSTEM 与本机 Administrators 可读。计划任务以 SYSTEM 身份运行并在开机时启动。
启动和请求日志写入 `data\wren-adapter.log`，默认日志级别为 `INFO`。每个 Adapter 响应都包含 `requestId`，可使用 customerapp 异常中的同一标识检索完整方法调用链和 traceback；如需降低成功链路日志量，可在 `config\wren.env` 中设置 `WREN_LOG_LEVEL=WARNING` 后重启计划任务。

## 无人值守与自动化安装

CI、自动化发布或无交互终端时，仍可显式传入参数。无终端时如果未提供实例 ID，安装器会立即报错，不会持续等待输入。

Linux：

```bash
sudo bash customer/wren/installer/install-wren-linux.sh \
  --instance-id tenant-10000-mcp-20001 \
  --extras mysql,postgres \
  --environment-file /tmp/wren.env \
  --profile-file /tmp/profiles.yml
```

Windows：

```powershell
& .\customer\wren\installer\install-wren-windows.ps1 `
  -InstanceId "tenant-10000-mcp-20001" `
  -Extras "mysql,postgres" `
  -EnvironmentFile "C:\Temp\wren.env" `
  -ProfileFile "C:\Temp\profiles.yml"
```

Linux 可通过 `--help` 查看完整参数；Windows 可通过 `Get-Help .\customer\wren\installer\install-wren-windows.ps1 -Detailed` 查看脚本参数。

## 配置 Customer Runtime

安装成功后，脚本会输出实际目录。customerapp 至少配置：

```text
ENTERPRISE_MCP_WREN_ENABLED=true
ENTERPRISE_MCP_WREN_BASE_URL=http://127.0.0.1:8091
ENTERPRISE_MCP_WREN_PROJECT_ROOT=<脚本输出的项目根目录>
ENTERPRISE_MCP_WREN_INSTANCE_DIR=<脚本输出的 state 目录>
```

安装器会在配置目录生成权限受限的 `customerapp-wren.env`，其中包含同一实例的
`ENTERPRISE_MCP_WREN_ADAPTER_SERVICE_TOKEN`、`ENTERPRISE_MCP_WREN_ADMIN_TOKEN`、
项目根目录和 loopback 地址。customerapp 服务应直接加载该文件；重复安装保留两枚 Token，
避免正在使用的浏览器 Session 和 BFF 调用凭据无故失效。

Wren 已由 systemd/计划任务托管时，`ENTERPRISE_MCP_WREN_EXECUTABLE` 保持为空，避免 customerapp 重复启动第二个 Adapter。

同一台服务器部署多个客户实例时，每个实例必须使用不同的 `--port`/`-Port`，并给对应 customerapp 配置相同的 `ENTERPRISE_MCP_WREN_BASE_URL`。

## 重复安装与回退

重复运行安装器会：

- 保留客户 project、profiles 和密钥环境文件，除非显式传入替换文件；
- 把当前 runtime 和虚拟环境保存为 `runtime.previous`、`venv.previous`；
- 安装新的 Wren runtime 并重启；
- 健康检查失败时同时恢复 `runtime.previous` 和 `venv.previous`。

每次安装都会创建新的 Python 虚拟环境，健康检查成功后保留上一套环境用于单版本回退。跨大版本升级前仍应备份实例状态目录，并在测试实例验证 MDL、驱动和数据库方言。
