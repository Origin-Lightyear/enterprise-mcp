# WrenAI 官方部署与本仓库定制差异评估

> 调研日期：2026-09-17  
> 官方当前主线快照：[`871118e94f1525c401d867074c05e7e8eefca1cc`](https://github.com/Canner/WrenAI/commit/871118e94f1525c401d867074c05e7e8eefca1cc)  
> 本仓库 Wren 锁定快照：`be1f9b57d2664aeb8287eef3eae3d931d90da3b9`，`wrenai 0.14.0`

## 一、结论

1. **必须区分两代官方产品。** 当前 `main` 已经是面向 Agent 的 Python CLI/SDK、MDL context layer 和进程内 Rust `wren-core`，安装主路径不使用 Docker。用户印象中的多镜像 Docker 部署是旧产品 **Wren GenBI Classic**；官方将其保留在 `legacy/v1` / `v1-final`，并明确说明不再提供新功能或安全修复。来源：[当前 README 的迁移说明](https://github.com/Canner/WrenAI/blob/871118e94f1525c401d867074c05e7e8eefca1cc/README.md#L228-L233)、[当前安装页](https://docs.getwren.ai/oss/get_started/installation)、[Classic 安装页](https://docs.getwren.ai/oss/installation)。
2. **本仓库不是完整官方 WrenAI，也不是 Classic Docker 全栈。** 它是一个面向 `enterprise-mcp` 的客户内网定制组件：复制官方 `core/wren` Python 包，新增 loopback HTTP Adapter，由 Java `customerapp` 调用，并用 systemd / Windows 计划任务托管。它故意不部署官方 UI、AI Service、Qdrant、Ibis Server，也不暴露官方 Wren MCP Server。
3. **本仓库当前还不是可直接交付业务查询的完整 Wren 实例。** `customer/wren/project` 只有项目元数据和说明，没有真实 `models/*/metadata.yml`、`knowledge/`、业务关系或编译后的 `target/mdl.json`；示例 profile 也只是占位连接。必须为具体客户完成数据源、MDL、口径、权限和真实数据库验证。
4. **源码子树完整不等于产品完整。** 对比结果显示 `customer/wren/upstream` 与锁定提交 `be1f9b5` 的官方 `core/wren` 子目录逐文件一致；但它没有官方仓库其余 Rust Core、MDL Schema、SDK、文档和构建工程，而且没有 Classic 全栈组件。当前官方 `main` 相对该锁定提交还领先 12 个提交：[官方比较](https://github.com/Canner/WrenAI/compare/be1f9b57d2664aeb8287eef3eae3d931d90da3b9...main)。

## 二、官方当前 OSS：安装、初始化、启动和配置

### 2.1 产品形态

当前官方架构分为 Agent workflow、project context、planning engine 和 execution layer。调用链是 Agent Skill -> Wren CLI/Python SDK -> `sqlglot`/CTE/policy -> PyO3 `wren-core` -> 数据源 connector；它不是一组常驻 Docker 微服务。来源：[官方架构](https://docs.getwren.ai/oss/reference/architecture)、[固定提交架构源码](https://github.com/Canner/WrenAI/blob/871118e94f1525c401d867074c05e7e8eefca1cc/docs/core/reference/architecture.md#L25-L50)。

当前 `wrenai` 包版本为 `0.14.0`，要求 Python 3.11+；DuckDB 默认包含，其他数据库和 memory/UI/MCP 按 optional extras 安装。来源：[官方 pyproject.toml](https://github.com/Canner/WrenAI/blob/871118e94f1525c401d867074c05e7e8eefca1cc/core/wren/pyproject.toml#L5-L10)、[`wren-v0.14.0` Release](https://github.com/Canner/WrenAI/releases/tag/wren-v0.14.0)。

### 2.2 推荐安装

官方现行安装页优先安装一个 Agent discovery skill：

```bash
npx skills add Canner/WrenAI
# 多个 Agent
npx skills add Canner/WrenAI --agent '*'
# 或
curl -fsSL https://raw.githubusercontent.com/Canner/WrenAI/main/skills/install.sh | bash
```

然后重新开启 Agent 会话，在目标项目目录要求 `/wren` 完成环境检查、Python 依赖、连接 profile、项目脚手架和首个查询。Wren 0.8 起只安装一个 discovery stub，`onboarding`、`usage`、`generate-mdl` 等流程由 CLI 按需提供。来源：[官方安装页](https://docs.getwren.ai/oss/get_started/installation)、[安装页原文](https://docs.getwren.ai/raw-docs/oss/get_started/installation.md)。

手工安装的最小可复现路径为：

```bash
python3 -m venv ~/.venvs/wren
source ~/.venvs/wren/bin/activate
pip install "wrenai[memory,main]"
wren version
```

数据库 connector 通过 extra 增加，例如 PostgreSQL 使用 `pip install "wrenai[memory,main,postgres]"`。来源：[官方 Quickstart](https://docs.getwren.ai/oss/get_started/quickstart)、[连接数据库指南](https://docs.getwren.ai/oss/guides/connect)。

### 2.3 初始化与首次查询

```bash
# 1. 创建并检查连接 profile
wren profile add customer-primary --ui
# 也可使用 --interactive 或 --from-file profile.yml
wren profile list
wren profile debug

# 2. 初始化项目并绑定 profile
mkdir customer-wren && cd customer-wren
wren context init
wren context set-profile customer-primary

# 3. 生成/维护 models、relationships、views、cubes、knowledge 后构建
wren context validate
wren context build
wren memory index

# 4. 查询或校验
wren dry-plan --sql "SELECT ..."
wren dry-run --sql "SELECT ..."
wren query --sql "SELECT ..."
```

`wren context init` 生成 `wren_project.yml`、`models/`、`views/`、`cubes/`、`relationships.yml` 和 `knowledge/`；构建产物是 `target/mdl.json`，memory 索引位于 `.wren/memory/`。来源：[官方 Quickstart](https://docs.getwren.ai/oss/get_started/quickstart)、[项目管理指南](https://docs.getwren.ai/oss/guides/manage_project)。

当前模式没有必须长期启动的统一 Web 首页。CLI 按命令运行；需要 MCP 时可执行 `wren serve mcp`，该 MCP Server 在同一进程内使用已编译 MDL 和 profile。来源：[官方 MCP 指南](https://docs.getwren.ai/oss/guides/mcp)。

### 2.4 配置位置

| 范围 | 官方当前配置 |
|---|---|
| 全局 | `~/.wren/profiles.yml`、`~/.wren/config.yml`、`~/.wren/.env`；`WREN_HOME` 可覆盖 |
| 项目 | `wren_project.yml`、`models/`、`views/`、`cubes/`、`relationships.yml`、`knowledge/rules/`、`knowledge/sql/` |
| 派生文件 | `.wren/memory/`、`target/mdl.json`，不建议提交 |
| 密钥解析 | 进程环境 -> 当前目录 `.env` -> 项目 `.env` -> `~/.wren/.env` |
| 项目定位 | `--path` -> `WREN_PROJECT_HOME` -> 从 cwd 向上查找 -> 全局默认项目 |
| profile 定位 | 显式连接参数 -> 项目绑定 profile -> 全局 active profile -> legacy connection 文件 |

来源：[官方 Operational Reference](https://docs.getwren.ai/oss/reference/operational)。

## 三、官方旧版 Classic Docker：多镜像如何启动

### 3.1 状态和入口

旧安装页仍在线，但在官方导航中属于 **Wren GenBI Classic · Sunset**。它要求 Docker Desktop 4.17+，下载 `0.29.2` launcher，launcher 收集 LLM 配置、拉起容器并打开 `http://localhost:3000`。来源：[Classic 安装页](https://docs.getwren.ai/oss/installation)、[安装页原文](https://docs.getwren.ai/raw-docs/oss/installation.md)、[`0.29.2` Release](https://github.com/Canner/WrenAI/releases/tag/0.29.2)。

Linux 示例：

```bash
curl -L https://github.com/Canner/WrenAI/releases/download/0.29.2/wren-launcher-linux.tar.gz \
  | tar -xz
./wren-launcher-linux
```

也可以预填 OpenAI：

```bash
./wren-launcher-linux \
  -llm-provider openai \
  -openai-api-key YOUR_OPENAI_API_KEY \
  -openai-generation-model GENERATION_MODEL_NAME
```

Windows 使用 `wren-launcher-windows.zip`，解压后以管理员身份运行。Launcher 会在 `~/.wrenai` 准备工程，下载 Compose/.env，执行 Compose，等待 UI 和 AI Service 就绪。来源：[官方 Launcher 源码](https://github.com/Canner/WrenAI/blob/v1-final/wren-launcher/commands/launch.go)。

### 3.2 Compose 服务和镜像

冻结基线 `v1-final` 的 Compose 有 6 个服务：

| Compose 服务 | 镜像 | 职责 |
|---|---|---|
| `bootstrap` | `ghcr.io/canner/wren-bootstrap:${WREN_BOOTSTRAP_VERSION}` | 初始化共享 Engine 配置和空 MDL |
| `wren-engine` | `ghcr.io/canner/wren-engine:${WREN_ENGINE_VERSION}` | 语义引擎与 SQL 端口 |
| `ibis-server` | `ghcr.io/canner/wren-engine-ibis:${IBIS_SERVER_VERSION}` | 数据源执行/函数等 Ibis 服务 |
| `wren-ai-service` | `ghcr.io/canner/wren-ai-service:${WREN_AI_SERVICE_VERSION}` | LLM、RAG、SQL 生成与修正管线 |
| `qdrant` | `qdrant/qdrant:v1.15.0` | 向量存储 |
| `wren-ui` | `ghcr.io/canner/wren-ui:${WREN_UI_VERSION}` | Next.js/Apollo UI、SQLite、服务编排入口 |

来源：[官方 v1-final docker-compose.yaml](https://github.com/Canner/WrenAI/blob/v1-final/docker/docker-compose.yaml)。

`data` volume 保存 bootstrap/engine 配置、Qdrant 数据和 UI SQLite；`${PROJECT_DIR}/data`、`${PROJECT_DIR}/config.yaml`、`${PROJECT_DIR}/.env` 分别挂入 Engine/AI Service。仅 UI `${HOST_PORT}:3000` 和 AI Service `${AI_SERVICE_FORWARD_PORT}:5555` 映射到主机，其余服务走 `wren` bridge network。来源同上。

### 3.3 Classic 配置和初始化

手工 Compose 的配置主件是：

- `docker/.env`：平台、端口、各镜像版本、项目目录、LLM key、遥测、主机映射端口；示例见[官方 `.env.example`](https://github.com/Canner/WrenAI/blob/v1-final/docker/.env.example)。
- `docker/config.yaml`：LLM、embedder、engine、Qdrant document store、SQL generation/correction 等 pipeline 与阈值；示例见[官方 `config.example.yaml`](https://github.com/Canner/WrenAI/blob/v1-final/docker/config.example.yaml)。
- bootstrap 首次创建 `config.properties`、开启 dynamic fields、创建 `mdl/` 和空 `mdl/sample.json`；见[官方 init.sh](https://github.com/Canner/WrenAI/blob/v1-final/docker/bootstrap/init.sh)。

冻结 `v1-final` 示例版本为 product `0.29.1`、engine `0.22.0`、AI Service `0.29.0`、Ibis `0.22.0`、UI `0.32.2`、bootstrap `0.1.5`。这些是 tag 内示例值，不能与 launcher Release `0.29.2` 混称为同一版本。来源：[v1-final `.env.example`](https://github.com/Canner/WrenAI/blob/v1-final/docker/.env.example)。

## 四、本仓库定制版如何初始化、配置和启动

### 4.1 实际组成和调用链

```text
Agent -> customerapp /mcp
      -> cloud planning plan
      -> WrenDatabaseTool
      -> 127.0.0.1:8091 Customer Wren Adapter
      -> vendored wrenai/WrenEngine + wren-core-py
      -> 客户数据库
```

本仓库的 `customer/wren/upstream` 是官方 `core/wren` 在 `be1f9b5` 的完整副本；新增 `adapter/server.py` 提供 `/internal/query`、`/internal/context`、`/internal/datasources`、`/internal/dry-plan`、`/internal/dry-run` 等内部接口。Adapter 只监听 `127.0.0.1`，不启动官方 MCP Server。

与官方当前 Agent 工作流不同，自然语言到 SQL 由 Adapter 直接调用员工请求级 OpenAI-compatible `/chat/completions`，然后用 `sqlglot` 校验只读单语句、拒绝普通 `SELECT *`、推导列来源，再交给 `WrenEngine` 查询。它没有走官方 Skill + memory recall/store 的完整流程。

### 4.2 生产安装与启动

Linux：

```bash
sudo bash customer/wren/installer/install-wren-linux.sh
```

Windows 管理员 PowerShell：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
& .\customer\wren\installer\install-wren-windows.ps1
```

两端默认进入交互向导，选择实例 ID、端口、安装/状态/配置目录、数据库 extras、`wren.env`、`profiles.yml` 和是否立即启动。Linux 注册 `enterprise-wren-<instance-id>.service`；Windows 注册以 SYSTEM 启动的 `EnterpriseMcp-Wren-<instance-id>` 计划任务。两端创建独立 venv、安装本地 `wrenai` 与固定 `wren-core-py==0.8.0`、只绑定 loopback，并对 `/internal/health` 做启动检查和单版本回退。

开发环境可以直接执行：

```bash
customer/wren/launcher/run-adapter.sh \
  /absolute/path/to/customer/wren/project \
  8091 \
  /absolute/path/to/customer-instance-state
```

或 Windows：

```powershell
& .\customer\wren\launcher\run-adapter.ps1 `
  -ProjectRoot "D:\customer\wren" `
  -Port 8091 `
  -InstanceDir "D:\customer\wren\instances\tenant-10000-mcp-20001"
```

### 4.3 必须补齐的初始化

1. 复制 `installer/profiles.yml.example`，填写数据源类型、host、port、database、user；密码保留 `${CUSTOMER_DB_PASSWORD}` 占位符。
2. 复制 `installer/wren.env.example` 到实例密钥目录，填写真实密码，禁止提交。
3. 在 `project/models/<model>/metadata.yml` 建立客户表/视图模型，在 `relationships.yml` 建关系，在 `cubes/` 建业务指标；需要时增加 `knowledge/rules/` 和经过确认的 NL-SQL 示例。
4. 用锁定 Wren CLI 执行 `wren context validate`、`wren context build`；启用 memory 才执行 `wren memory index`。当前安装器默认没有安装 `memory` extra，也不负责生成业务 MDL。
5. 用 `/internal/dry-run` 或真实查询验证数据库驱动、凭据、方言、数据权限、行数上限和列 lineage。`/internal/health` 只证明 Adapter 能加载 MDL，不证明数据库连通。

### 4.4 customerapp 配置

```text
ENTERPRISE_MCP_WREN_ENABLED=true
ENTERPRISE_MCP_WREN_BASE_URL=http://127.0.0.1:8091
ENTERPRISE_MCP_WREN_PROJECT_ROOT=<实例项目根目录>
ENTERPRISE_MCP_WREN_INSTANCE_DIR=<实例状态目录>
```

Wren 已由 systemd/计划任务托管时，`ENTERPRISE_MCP_WREN_EXECUTABLE` 必须留空，避免 Java 再启动第二个 Adapter。同机多实例必须分配不同端口。默认连接超时 2 秒、读取超时 60 秒、启动超时 30 秒。

## 五、官方与定制版差异

| 项目 | 当前官方 OSS | Classic Docker（Sunset） | 本仓库定制版 |
|---|---|---|---|
| 主要入口 | Agent Skill + CLI/SDK | Launcher + Web UI | Java `customerapp` + loopback Adapter |
| 部署形态 | Python 包，Rust Core 进程内 | 6 个 Compose 服务 | Java Fat JAR 外加 1 个 Python sidecar |
| 初始化 | `profile` + `context init/build` + memory | Launcher/Compose + UI onboarding | 安装器仅部署 runtime；客户 MDL/profile 需另行补齐 |
| 自然语言规划 | Agent 按 Skill 使用 context/memory 后生成 SQL | AI Service + Qdrant pipeline | Adapter 直接调用员工 LLM 配置 |
| MCP | 可选 `wren serve mcp` | 旧全栈由 UI/服务编排 | 明确禁用官方 Wren MCP，只暴露 customerapp `/mcp` |
| UI | OSS 主线无 Classic 管理 UI | `wren-ui`，默认 3000 | 无 Wren UI |
| Memory | 可选 LanceDB | Qdrant | 默认未安装/未接入官方 memory 流程 |
| Profile | 默认 `~/.wren`，可用 `WREN_HOME` | `.env` + `config.yaml` + UI 数据库 | 每客户 `WREN_INSTANCE_DIR/.wren`，实例隔离 |
| 生命周期 | CLI/SDK 由宿主决定 | Docker Compose | systemd/Windows 计划任务，独立于 JAR 升级 |
| 安全边界 | OSS 引擎能力；高级权限属商业版 | Classic 应用自己的旧边界 | loopback、只读 SQL AST、MDL digest、请求级员工 LLM、Java 权限/审计 |
| 更新状态 | 当前维护 | 官方明确 Sunset | 锁定旧于 main 12 个提交，需自主管理补丁 |

## 六、“现在 Wren 是完整的吗”的分层判断

| 判断对象 | 结论 | 依据 |
|---|---|---|
| `customer/wren/upstream` 相对锁定 `core/wren` | **完整** | 逐文件对比一致 |
| 相对当前官方 `main` | **不是当前最新** | 锁定提交落后当前主线 12 个提交；[官方 compare](https://github.com/Canner/WrenAI/compare/be1f9b57d2664aeb8287eef3eae3d931d90da3b9...main) |
| 相对当前官方 OSS 仓库 | **不完整** | 仅复制 `core/wren` 子树，未包含仓库其余 Core/SDK/Schema/文档/构建部分 |
| 相对当前官方 OSS 功能路径 | **部分接入** | 复用 MDL planner/connector，但未接入官方 Skill、memory、官方 MCP、SDK 集成和 GenBI 工具全流程 |
| 相对 Classic Docker 产品 | **完全不是同一部署** | 没有 UI、AI Service、Qdrant、Ibis、bootstrap 和 Compose |
| 当前客户业务实例 | **未完成** | MDL 模型、knowledge、编译 manifest 和真实凭据均未落地 |
| 生产交付 | **尚不能判定完成** | 真实 systemd/Windows Task、客户数据库、员工 LLM、管理员接口保护、升级回退尚无环境级验收证据；分发目录还缺 Apache 2.0 `LICENSE` 正文 |

此外，当前官方 OSS 本身也不能理解成“包含官方全部商业能力”。官方明确把行/列级安全与用户组访问控制、商业 GenBI UI/仪表盘/嵌入/API、Scenario AI、先进安全审计、支持与 SLA 等放在 Cloud / self-hosted Enterprise Plus。来源：[官方 OSS 与商业边界](https://github.com/Canner/WrenAI/blob/871118e94f1525c401d867074c05e7e8eefca1cc/README.md#L148-L157)。

## 七、上线前最低闭环

1. 决定产品目标：本项目应继续定位为“客户内网语义查询 sidecar”，不要追求复刻已 Sunset 的 Classic UI 全栈。
2. 为首个真实客户建立完整 MDL、关系、口径和 knowledge，并把 MDL digest 纳入发布与审计。
3. 固定所有 Python wheels/哈希，而不只固定 `wren-core-py`；评估从 `be1f9b5` 合入当前 12 个 connector/CTE 修复。
4. 随分发包补齐 Apache 2.0 `LICENSE` 正文和上游声明，执行 Python/Rust 许可证与漏洞扫描。
5. 对 `/internal/wren/**` 落实管理员鉴权；不能只依赖路径名或 loopback 假设。
6. 在 Linux systemd 和 Windows SYSTEM 任务上分别执行安装、重启、断电恢复、升级、失败回退、多实例端口冲突测试。
7. 用真实数据库和真实员工 LLM 做端到端验收：profile -> MDL build -> plan -> 权限审查 -> 查询 -> lineage -> 行数/超时 -> 审计；健康检查不能替代该验收。

## 八、资料基线说明

本报告仅使用 WrenAI 官方 GitHub、官方文档及其直接链接的一手资料。官方文档同时保留当前 OSS 和 Classic Sunset 两套路由，因此引用时明确标注代际。对 Docker 的精确镜像和配置采用不可变的 `v1-final` tag；对当前产品采用调研时 `main` 的固定提交 `871118e`，避免后续页面变化造成结论漂移。
