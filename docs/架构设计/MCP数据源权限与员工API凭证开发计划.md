# MCP 数据源权限与员工 API 凭证开发计划

## 一、目标

重建 Tenant 员工权限系统，使权限不再依赖自然语言、MCP 方法、Java 方法、业务字段或 LLM 裁决，并保证内部 MCP 与公开 MCP 使用同一套确定性执行规则。

最终规则：

- 数据库数据源由 Tenant 按角色配置查询、新增、修改、删除权限。
- API 数据源强制继承来源系统用户权限，Tenant 只维护员工在该数据源中的身份凭证。
- 数据库权限检查最终 SQL；无法解析、未知类型、多语句以及未授权操作一律拒绝。
- API 调用必须使用当前员工凭证；缺失、失效或来源系统拒绝时直接失败，不得回退共享账号。
- Platform 不参与数据源权限和第三方凭证管理。
- 客户 MCP 不引入业务数据库，凭证事实数据保存在 Tenant 数据库。

## 二、系统职责

### Tenant 后端

- 保存员工、角色、数据库数据源权限和员工 API 凭证。
- 通过已配置的 MCP 地址读取 Runtime 数据源清单。
- 接收 Runtime 的一次性凭证申请，并只向该租户已登记的固定 Runtime 地址反向投递凭证。
- 加密保存凭证，员工身份只允许账号密码或唯一标识两种类型，管理接口永不回显凭证正文。
- 只保存一份 Tenant MCP 根密钥，按租户和 Runtime 实例派生独立通信 Token，并按租户和 MCP Server 派生凭证密钥。
- 保存数据源权限决策与执行审计。

### 客户 MCP Runtime

- 提供当前 Runtime 的数据库与 API 数据源描述。
- 在最终 SQL 执行前进行操作分类和确定性授权。
- 在 API 调用前生成一次性随机请求编号，并仅接收 Tenant 对本机待处理请求的反向凭证投递。
- 隔离不同员工的第三方 API 登录会话。
- 内部 MCP 与公开 MCP 共用同一请求身份和数据源执行约束。

### Tenant 前端

- 用数据库数据源权限矩阵替换自然语言禁止规则和敏感规则。
- 在员工管理中提供 API 数据源身份凭证配置。
- 只展示凭证类型和是否已配置，不展示凭证正文。
- 展示基于数据源、操作和执行结果的新审计信息。
- 在系统设置中按 MCP 卡片展示运行信息，并按需查看、隐藏和复制当前 Runtime 的“通信密钥”。

### Platform

- 不参与本功能。

## 三、数据模型

### 角色数据源权限

使用 `tnt_role_datasource_permission` 表保存：

- 租户编号
- MCP Server 编号
- 数据源稳定编号
- 角色编号
- 是否允许查询
- 是否允许新增
- 是否允许修改
- 是否允许删除
- 创建时间和更新时间

业务唯一键为租户编号、MCP Server 编号、数据源稳定编号和角色编号。没有记录等同于全部禁止。

### 员工 API 凭证

使用 `tnt_employee_api_credential` 表保存：

- 租户编号
- MCP Server 编号
- API 数据源稳定编号
- 员工编号
- 凭证类型
- 单一加密凭证字段
- 创建时间和更新时间

业务唯一键为租户编号、MCP Server 编号、API 数据源稳定编号和员工编号。加密算法所需参数封装在密文中，不扩散为业务字段。

## 四、接口

### Tenant 管理接口

- 查询租户所有 MCP 的数据源清单。
- 查询和保存角色的数据库数据源权限。
- 查询员工 API 凭证配置状态。
- 新增或替换员工 API 凭证。
- 删除员工 API 凭证。

### Runtime 内部接口

- 返回 Runtime 数据源描述，包括稳定编号、显示名称、数据源类型和支持的员工身份类型；数据库 CRUD 权限不依赖 Runtime 当前已实现的方法。

### Tenant 内部接口

- Runtime 按租户、实例、员工和 API 数据源申请当前凭证；申请响应不含凭证正文。
- Tenant 将凭证反向投递到该实例在 Tenant 登记的固定地址，Runtime 只接受本机待处理的一次性随机请求编号。

敏感接口必须通过当前实例唯一的 `X-Tenant-Mcp-Token` 和 HTTPS 访问，并校验租户与 Runtime 实例归属。
升级、数据源目录、凭证申请和凭证反向投递复用同一个实例 Token；Runtime 不持有 Tenant 根密钥。

## 五、执行规则

### 数据库

- 角色权限取启用角色授权的并集。
- 新数据源、新角色和无授权员工默认拒绝。
- Wren 最终 SQL 使用 `sqlglot` AST 分类。
- 当前 Wren 只执行只读查询；未来数据库写能力必须接入同一授权接口。
- 不建设表、字段和敏感数据元数据层。

### API

- 每次请求使用已验签的当前员工身份。
- 请求内最多解析一次同一数据源凭证。
- 第三方会话按租户、Runtime、数据源、员工和凭证更新时间隔离。
- 没有凭证、类型不支持、解密失败或第三方拒绝时失败关闭。
- 禁止使用共享账号兜底。

## 六、旧能力退出

- 移除自然语言禁止规则和敏感规则的页面、接口和运行时读取。
- 移除 LLM 权限裁决、结果脱敏和相关决策缓存。
- 保留部门、角色、员工和审计能力。
- 首个版本不删除旧规则表，确保数据库回滚和历史核查；旧表不再参与运行。
- Flyway 仅新增迁移，不修改已应用的 V1、V2。

## 八、验证结果

- Tenant Maven 共 30 个测试通过；覆盖通信 Token 派生、租户隔离、实例信息缺失拒绝、两种员工身份类型和数据库 CRUD 权限保存。
- 客户侧 Maven reactor 通过：共享契约 4 个测试、Runtime 72 个测试、客户应用 52 个测试，其中 1 个真实环境测试按条件跳过。
- Wren Adapter 共 56 个测试通过，覆盖只读 SQL、写 SQL、多语句和字段血缘约束。
- Tenant 前端展示逻辑共 11 个测试通过；覆盖两种员工身份结构、历史类型提示和数据库四项权限配置。
- 数据源权限页、员工 API 身份页及凭证弹窗已在 1440px 桌面端和 390px 移动端完成截图检查，无页面级横向溢出或控件重叠。
- 系统设置页已在 1440px 桌面端和 390px 移动端完成真实浏览器检查；桌面卡片为 360px × 480px，移动端卡片保持 480px 高并适配可用宽度，长名称、长版本和长更新说明均无裁切、重叠或横向溢出。
- 通信密钥的查看、隐藏和复制交互已通过真实浏览器验证；复制内容为可直接配置 Runtime 的 `TENANT_MCP_TOKEN=<通信 Token>`。

## 九、验收标准

- 未配置数据库权限的员工无法查询对应数据源。
- SQL 操作类型与角色权限不匹配时，在数据库执行前被拒绝。
- API 数据源未配置员工凭证时无法调用。
- 两个员工不会共享金蝶登录身份或会话。
- API 凭证不会出现在管理查询响应、日志、审计、异常或 MCP 参数中。
- 新增 MCP 方法不会要求管理员新增权限规则；它自动继承所属数据源规则。
- 新增数据库数据源默认拒绝；新增 API 数据源默认要求员工凭证。
- 内部 MCP、公开 MCP 和调试身份路径均执行相同数据源约束。

## 十、部署配置与兼容边界

- 金蝶 Runtime 必须配置 `ENTERPRISE_MCP_K3_APP_ID`（金蝶应用编号）和 `ENTERPRISE_MCP_K3_APP_SECRET`（金蝶应用密钥）；两者属于数据源连接配置，不属于员工身份。
- Tenant 管理员在员工 API 身份页面为金蝶填写“唯一标识”，内容为该员工在金蝶中的用户名，不填写员工密码。
- 历史 `TOKEN` 或 `API_KEY` 类型记录不会静默转换，管理页面标记为“需重新配置”，Runtime 解析时失败关闭。
- 当前 Wren 工具仍只执行查询。提前授予新增、修改或删除权限只保存长期策略，不会让尚未实现的写工具获得执行能力。
