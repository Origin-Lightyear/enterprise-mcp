# 混合只读执行与权限审查设计

## 目标与边界

本方案支持一个员工请求同时包含客户数据库查询和客户内网 API 查询。Cloud Control Plane 只负责编排，客户 Runtime 负责身份、权限、版本绑定、执行、脱敏和审计，Wren 只负责数据库语义查询。

第一版仅允许只读操作：

- Wren 只能生成并执行一条只读 SQL；一条 SQL 可以包含 JOIN、CTE、聚合、子查询和 UNION。
- API 能力必须声明 `operationMode=READ_ONLY`。
- 写入、审批、创建、更新和删除能力由 Cloud 与 Runtime 双重拒绝。
- 多源读取不声明分布式事务；任一步失败时不返回部分业务结果。

## 组件职责

| 组件 | 负责 | 不负责 |
|---|---|---|
| Cloud Control Plane | 根据 Runtime Catalog 生成完整计划；优先批量能力；将数据库需求划分为有业务意义的 Wren 子问题 | 不接收 Tenant 权限规则、MDL、执行结果或权限审查正文 |
| Tenant | 保存员工自然语言 `denyRules`、`sensitiveRules` 和员工 LLM 配置 | 不维护 MDL 字段标签或云端规划模板 |
| Runtime | 校验计划绑定；固定权限与 MDL 快照；调用员工 LLM 审查一次；执行、脱敏、通知和审计 | 不重新规划，不在执行步骤中再次调用权限模型 |
| Wren Adapter | 使用员工 LLM 生成一条 SQL；AST 校验只读性；执行查询；自动计算输出列来源 | 不理解 Tenant 权限，不决定员工能否访问数据 |

共享 Contract 只包含执行语法、能力元数据和版本绑定字段，不包含提示词、拆解策略或计划生成实现。

## 请求时序

1. Runtime 校验 Agent 签名、租户状态、员工状态和请求防重放信息。
2. Runtime 请求 Cloud 生成计划。
3. Runtime 校验 `planContractVersion`、租户、员工、实例、Runtime 版本、制品摘要和 Catalog 摘要。
4. Runtime 拒绝未登记能力、能力版本不匹配和非只读能力。
5. 计划包含 Wren 时，Runtime 从 Adapter 读取同一响应中的 MDL 与 `mdlDigest`。
6. 存在权限规则时，Runtime 使用员工 LLM 对原始请求、完整计划、权限规则、相关 Tool Schema 和本地 MDL 审查一次；规则为空时跳过模型调用。
7. `deny`、最终 `uncertain`、模型异常或格式错误均在执行前失败关闭。
8. Runtime 先持久化本地权限审计和 Tenant 审计 Outbox，再进入执行器。
9. Wren 请求携带请求级员工 LLM 配置与预期 `mdlDigest`；摘要变化时拒绝执行并要求重新请求。
10. Runtime 顺序执行步骤；`foreach` 默认串行，超限、超时、取消或任一步失败时停止，不返回部分结果。
11. Runtime 只在最终对外结果上应用敏感字段脱敏，并返回数据和安全 `executionReceipt`。

## Wren 查询完整性

- SQL 必须通过 `sqlglot` 解析为唯一一条 Query。
- 禁止 DDL、DML、管理命令、多语句和普通 `SELECT *`；`COUNT(*)` 可以使用。
- 每个输出表达式必须有稳定列名。
- Adapter 根据 SQL AST 与 MDL 自动计算 `columnLineage`，不采用 LLM 自报的字段来源。
- 聚合和计算列保留全部 MDL 源字段，因此采购成本的平均值、合计值和派生利润默认继承敏感性。
- 返回行数超过完整性限制时直接失败，禁止截断后冒充完整结果；应让 Wren 在数据库内聚合。
- 结果为空属于成功，不代表数据错误。

## 权限与脱敏

Tenant 管理员只编写自然语言规则。MDL 只需维护表、字段、主键、关系以及字段中文含义，不要求维护 `securityTags` 或独立业务指标口径。

权限模型输出：

- `decision=deny`：整份计划不执行。
- `decision=allow`：允许执行；需要脱敏时返回固定 API 字段路径或 Wren `Model.field` 源字段。
- `uncertain=true`：失败关闭。

字段描述不足本身不直接失败。模型继续结合表名、字段名、关系、用户请求和计划判断；使用全部上下文后仍无法确定时才返回 `uncertain`。

敏感原值可以在本地 `ExecutionContext` 中作为后续只读关联键使用，但不得进入日志、进度通知、审计正文或执行回执。最终输出不包含受限字段时，脱敏指令为正常空命中，不应报错。

## 进度、回执与审计

Agent 可收到以下业务级通知：计划生成、权限校验、步骤进度、`foreach` 降级原因与限频进度、完成、失败、取消和超时。通知不包含 SQL、URL、Java 方法名、能力 ID、权限原文或字段路径。

成功响应包含：

- `data`：完成最终脱敏的业务结果。
- `executionReceipt`：计划编号、状态、统一 `asOf`、一致性模式、业务操作描述、步骤数和起止时间。

当前普通数据库与 API 不提供严格时间点快照，因此回执使用 `BEST_EFFORT_CURRENT`，不得描述为严格 `asOf` 报表。

Runtime 在执行前同步刷盘权限决策摘要；本地审计失败则拒绝执行。Tenant 上报使用文件 Outbox 和 `auditId`，网络失败时保留并定时重试。审计只记录版本、摘要、能力集合、决策和规则 ID，不记录结果正文、权限原文、SQL、MDL 或密钥。

## 验收矩阵

| 场景 | 预期结果 |
|---|---|
| 无权限规则 | 跳过权限 LLM，继续机械校验和审计 |
| 禁止规则命中 | SQL/API 均不执行，员工收到安全业务提示 |
| 权限模型异常或最终不确定 | 失败关闭并提示稍后重试 |
| 手机号不在结果中 | 正常返回，不要求命中脱敏字段 |
| 手机号作为内部 API 关联键 | 原值仅在本地上下文使用，最终展示脱敏 |
| 聚合采购成本 | 根据 AST 列来源继承并执行财务脱敏 |
| 某门店没有销售记录 | 返回空行或零值，计划仍成功 |
| Wren 结果超过限制 | 整体失败，要求数据库内聚合 |
| API `foreach` | 通知降级原因和限频进度，默认串行 |
| 任一步失败、超时或取消 | 停止后续步骤，不返回部分业务结果 |
| Catalog、制品或 MDL 摘要变化 | 拒绝旧计划，要求发起新请求 |

## 生产验收边界

仓库自动化测试只能验证协议、校验器、脱敏与 Adapter 纯逻辑。上线前仍必须在客户环境验证真实 MDL、数据库驱动、员工模型、Tenant 权限接口、目标 API、MCP 进度通知、取消传播、Outbox 重试和 Agent 最终总结。
